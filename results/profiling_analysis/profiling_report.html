EDGE LLM PROFILING · MACBOOK AIR M2 · 8 GB

Quantization, workload length,
and the limits of comparison

Consolidated local results · November 16, 2026

Findings

Phi-3.1 Mini Q4 completed all four requested CPU workloads. Its measured generation throughput was 7.55–8.13 tokens/s for tg128 and 4.46–4.84 tokens/s for tg512. Memory pressure reached the warning level during parts of the session and later returned to normal. No allocation errors were found in the two newly launched runs. Phi Q8 remains unmeasured.

The existing Qwen server results show a quantization trade-off: Q4 generated tokens 20.5–46.3% faster than Q8 across the four conditions, while Q8 processed prompts 10.8–42.0% faster. The Q4 model file is 41.3% smaller than Q8. These are descriptive observations from three requests per condition.

Interpretation boundary. Phi uses CPU-only llama-bench tests. Qwen’s full-workload results use llama-server requests, with a different prompt and generation procedure. Separate Qwen llama-bench files explicitly record 99 GPU layers. Server logs do not record the exact offload count, so their backend is described as default server configuration, rather than assumed to be identical to those microbenchmarks. This dataset cannot establish an architecture-only Phi versus Qwen speed ranking.

4. Memory, missing measurements, and scope

  • Phi Q8: deliberately not run under the memory constraint. Its missing results are unavailable, never zero. Existing Qwen Q8 results are historical measurements and do not establish that Phi Q8 is safe.
  • Phi memory state: the monitored session moved between warning level 2 and normal level 1, with swap already active. The runner never observed critical level 4. Only the two newly launched workloads have captured error logs; the pre-existing 1024/128 run’s stderr was attached to its terminal.
  • Uncertainty: error bars are standard deviations, not confidence intervals. Phi CSVs contain aggregate statistics rather than individual repetitions. Three repetitions were observed or explicitly requested for the newly completed workloads; the earlier 256/128 CSV does not itself encode its repetition count.
  • Energy and quality: this performance report makes no accuracy or energy-efficiency claim. The files named “energy_response” contain completion timings, not joules or watt readings. Existing quality scores require their own rubric audit before a defensible quality comparison.
  • Duplicates: identical Qwen benchmark copies in the nested results folder are not counted as extra experiments. Pilot and ad hoc server CSVs are excluded from the main four-workload analysis. Earlier Phi server-status files describe a skipped server experiment; the completed CPU microbenchmarks are a separate experiment.

5. Conclusion

On this 8 GB M2 system, Phi-3.1 Mini Q4 completed the requested CPU benchmark matrix, with lower observed generation throughput in the longer tg512 tests. The existing Qwen server measurements favor Q4 for generation speed and file size, while Q8 shows higher prompt throughput. These results support configuration-specific conclusions. A controlled model-family comparison remains unmeasured because the available runs differ in compute backend and test method.

A future matched study would use the same backend, benchmark method, workload, cache settings, and recorded memory/thermal state for both model families. That follow-up has not been run here; no additional models were loaded for this analysis.
